# Next Portfolio Page

## Procedure

1. Inspect the existing route and nearby project pages.
2. Define the page goal in one sentence.
3. Keep the route simple under `src/app/projects/` when it is project-specific.
4. Reuse the current visual language: dark background, subtle glow, grid texture, honest status badges.
5. Keep copy beginner-readable and portfolio-ready.
6. Avoid new dependencies for layout or icons.
7. Run `npm run lint` and `npm run build` when practical.

## Project Standards

- Personal Portfolio pages should show what is deployed and active.
- AI Study Assistant pages should disclose mock data and no API connection.
- Python Study Utilities pages should show safe tool behavior and terminal commands.
- Buttons should lead to a real route, live site, GitHub, or clear placeholder only when honest.

## Guardrails

- Do not add fake production claims.
- Do not overbuild shared abstractions.
- Do not touch unrelated routes.
- Do not add backend behavior unless explicitly requested.
