# Portfolio Polish

## Procedure

1. Identify the project audience.
2. Identify the strongest product signal.
3. Check whether the current status is honest: prototype, mock data, dry-run, roadmap, or usable tool.
4. Improve the first impression before adding features.
5. Keep documentation aligned with what actually works.
6. Suggest one next iteration that increases portfolio value.

## Polish Targets

- Clear project title and purpose.
- Honest feature status.
- Strong demo flow.
- Clean responsive UI.
- README with run command and what the project demonstrates.
- No fake claims about AI, production readiness, or real data.

## Guardrails

- Do not add large dependencies only for visual polish.
- Do not make fake production claims.
- Do not hide prototype limitations.
- Prefer small visible improvements.
