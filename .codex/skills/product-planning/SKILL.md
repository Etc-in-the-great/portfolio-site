# Product Planning

## Procedure

1. Restate the idea in one sentence.
2. Identify the real user problem.
3. Define the smallest useful version.
4. Split requirements into `must have`, `nice to have`, and `not now`.
5. Identify the portfolio signal: what this shows about product ability or technical growth.
6. Choose the first implementation step.

## Guardrails

- Prefer one visible improvement per iteration.
- Avoid adding backend, database, auth, or heavy dependencies unless they are essential to the MVP.
- Use honest labels for unfinished features: `prototype`, `mock data`, `roadmap`, or `dry-run`.
- End with a practical next step, not a large roadmap.

## Output Shape

Use this compact structure:

- Goal
- User problem
- MVP slice
- Requirements
- Not now
- First step
