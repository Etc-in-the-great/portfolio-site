# Evidence-Driven Portfolio Workflow

Use this when updating portfolio pages, README content, project status, or case studies.

## Principle

Every claim should point to visible evidence:

- a deployed route,
- an interactive prototype,
- a terminal command,
- a README,
- a screenshot placeholder,
- or a working dry-run script.

## Checklist

- Is the status honest?
- Can a visitor see what works now?
- Does the page explain what is mock data, dry-run, or roadmap?
- Is the next step concrete?
- Does README match the actual project state?

## Avoid

- Fake production claims.
- Saying an AI feature is connected when it is mock data.
- Saying a Python tool renames files when it only previews.
- Overloading the homepage with every future idea.

## Good Labels

- `deployed / active`
- `interactive static prototype`
- `mock data`
- `dry-run`
- `roadmap`
- `no API connected yet`
