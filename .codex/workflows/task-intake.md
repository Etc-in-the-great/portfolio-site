# Task Intake Workflow

Use this before implementation when the request is vague, large, or product-facing.

## 1. Goal

Write the goal in one sentence:

- What should be better after this task?

## 2. User Problem

Identify the real problem:

- Who is this for?
- What pain does it reduce?
- What workflow does it improve?

## 3. Smallest Useful Version

Define the MVP slice:

- What is the smallest change that creates visible value?
- What can wait until later?
- What should not be built yet?

## 4. Requirements

Split into small requirements:

- Must have
- Nice to have
- Not now

## 5. Risk Check

Before editing, check:

- Which files are likely affected?
- Is this a UI, data, API, or documentation change?
- Is rollback easy?
- Are tests or build commands available?

## 6. Decision

State the implementation decision:

- Chosen approach
- Why it is simple enough
- What will be reviewed after
