# Scope Control Workflow

Use this when a request starts expanding into many features, pages, tools, or architecture decisions.

## Questions

- What is the single most valuable outcome for this turn?
- Which parts are required now?
- Which parts can become roadmap items?
- Does this need a new dependency, backend, API, database, or auth?
- Is the user asking for a real tool or a static prototype?

## Rules

- Prefer one project card, one page, one script, or one section per pass.
- Keep prototype work clearly labeled.
- Do not convert a static prototype into a backend system unless explicitly requested.
- Do not add hidden dependencies.
- Do not mix portfolio polish with unrelated feature work.

## Output

When scope is too large, respond with:

- `This turn`: what will be done now.
- `Later`: what belongs in the roadmap.
- `Not now`: what would overcomplicate the project.
