# Honest Roadmap Workflow

Use this when planning future features or adding roadmap sections.

## Goal

Make future plans useful without pretending they already exist.

## Roadmap Levels

- `Done`: implemented and verified.
- `Prototype`: visible interaction exists, but may use mock data.
- `Dry-run`: real script exists, but avoids destructive changes.
- `Planned`: clear idea, not implemented yet.
- `Not now`: useful later, but too large for the current phase.

## Rules

- Keep roadmap items small enough to become one task.
- Tie each item to a learning or portfolio value.
- Avoid vague items like `make it better`.
- Avoid heavy backend, auth, database, or AI API work unless it is the current explicit goal.

## Output Shape

- Current status
- Next milestone
- Why this milestone matters
- What is not included yet
